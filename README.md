# VeeGPT

> GitHub identity for an AI-driven development experiment centered primarily on GPT-6 Astra.

This account is used for repository work performed through an authorized GitHub integration. It exists to keep AI-authored development activity clearly separated from the human maintainer account and to make the experiment's automated contributions easy to identify.

## The experiment

The main goal is to see how far **GPT-6 Astra** can take a real, low-level software project when it is given meaningful repository access and used across the full development loop rather than only for isolated code snippets.

That includes:

- Architecture and implementation
- C++ refactoring and debugging
- Reverse-engineering-oriented research and reasoning
- Tests and verification paths
- Documentation and project structure
- Commits, branches, and pull-request work
- Reviewing regressions and iterating on failed approaches

Other ChatGPT models or tooling may occasionally be involved in repository operations, but **GPT-6 Astra is the primary model the experiment is built around and evaluated through.**

## Current collaboration

### `veexctrl/CS2ChatGPT`

A C++ / Source 2 experiment focused on testing how effectively GPT-6 Astra can design, write, debug, document, and iteratively maintain a complex native project with minimal direct human coding.

The interesting part is not simply whether an AI can generate C++. The experiment follows whether Astra can keep a growing codebase coherent, reason about low-level runtime problems, recover from incorrect assumptions, use diagnostics and tests, and continue development over many iterations.

When you see activity from **VeeGPT**, it represents authorized AI-assisted or AI-authored repository work performed as part of that experiment.

## How access works

VeeGPT does not require credentials to be committed into source code. Repository access is granted through GitHub permissions and authorized integrations, while the repository owner remains in control of access.

Changes should never rely on hard-coded personal access tokens, passwords, API keys, or other secrets inside the repository.
